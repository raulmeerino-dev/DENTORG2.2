## Cómo leer este documento

Cada flujo se reporta con esta estructura:

- **Pantalla origen** — ruta y archivo:línea del componente
- **Botón/acción** — etiqueta que ve el usuario
- **Handler frontend** — función que dispara la mutación
- **Función en `api.ts`** — wrapper HTTP
- **Endpoint backend** — método + path + archivo:línea
- **Modelo/tabla** — clase SQLAlchemy
- **Queries invalidadas** — claves de React Query refrescadas
- **Dónde debería verse el resultado** — pantalla/sección que debe actualizarse
- **Estado real** — uno o varios de: `funciona`, `funciona a medias`, `roto`, `solo frontend/local`, `no persiste tras refresh`, `usa fallback demo`, `falta endpoint`, `falta invalidación`
- **Evidencia** — citas concretas con `archivo:línea`
- **Gravedad** — `crítica` | `alta` | `media` | `baja`
- **Recomendación** — una frase

### A.4. Seleccionar paciente activo

- **Pantalla origen**: cualquier punto de entrada (sidebar pacientes, Hoy, Agenda fila de cita, Caja "Ver ficha")
- **Botón/acción**: clic sobre paciente
- **Handler frontend**: `setSelected(paciente)` — `pacientes/index.tsx:778`; en otros módulos `sessionStorage.setItem('dentcore_selected_patient_id', ...)`
- **Función en `api.ts`**: N/A
- **Endpoint backend**: N/A
- **Modelo/tabla**: N/A (estado UI)
- **Queries invalidadas**: N/A
- **Dónde debería verse el resultado**: ficha del paciente seleccionado
- **Estado real**: **funciona a medias**. El "paciente activo" usa **sessionStorage** + estado React local. Tras `setSelected`, NO se actualiza sessionStorage de forma consistente (solo se persiste en 4 sitios concretos: `pacientes/index.tsx:566`, `:706`, `:761`, `:779`). Si el usuario navega entre pacientes desde la lista usando otra vía, sessionStorage queda obsoleto. URL query `?paciente_id=` es la única fuente robusta (línea 209).
- **Evidencia**:
  - `pacientes/index.tsx:209`: `const requestedPatientId = searchParams.get('paciente_id') ?? sessionStorage.getItem('dentcore_selected_patient_id');`
  - `pacientes/index.tsx:210`: `const activeSummary = selected ?? pacientes.find((p) => p.id === requestedPatientId) ?? pacientes[0] ?? null;`
  - 4 invocaciones a `setSelected` (líneas 554, 564, 661, 778) sin `useEffect` espejo en sessionStorage.
- **Gravedad**: **alta**
- **Recomendación**: añadir `useEffect(() => { if (selected) sessionStorage.setItem('dentcore_selected_patient_id', selected.id); }, [selected]);` y al renderizar inicial, sincronizar `setSelected(activeSummary)` para que el primer pintado deje el estado consistente.

### A.5. Mantener paciente tras refrescar (F5)

- **Pantalla origen**: `/pacientes` (o cualquier ruta)
- **Estado real**: **funciona a medias / no persiste tras refresh** según camino.
  - F5 mientras estás en `/pacientes?paciente_id=xxx` ⇒ recupera correctamente (línea 209).
  - F5 mientras estás en `/pacientes` sin query param ⇒ usa sessionStorage si está, si no, primer paciente.
  - Si el sessionStorage es obsoleto (ver A.4), el paciente activo cambia silenciosamente al de la sessionStorage stale.
- **Gravedad**: **alta**
- **Recomendación**: tras seleccionar un paciente, actualizar la URL con `navigate('/pacientes?paciente_id=xxx', { replace: true })` para que la URL sea siempre canónica. Eliminar la dependencia silenciosa de sessionStorage como fuente única.
